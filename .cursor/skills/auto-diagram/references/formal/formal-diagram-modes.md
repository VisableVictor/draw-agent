# Formal Diagram Modes

这类任务的重点不是“看起来像”，而是“表达规范正确、语义清晰、行业识别度高”。

## 何时进入正式图法模式

当用户明确要求，或需求明显属于以下类型时，进入正式图法模式：

- `UML`
- `BPMN`
- `ArchiMate`
- `Cloud`
- `Network`
- `Security`
- `Data Analytics`
- `IoT`

## 判断信号

### UML

常见信号：

- 类图、时序图、组件图、部署图、状态图、活动图
- 软件设计建模
- 接口和模块关系

### BPMN

常见信号：

- 业务流程规范化
- 审批流
- 角色泳道
- 网关、事件、任务流

### ArchiMate

常见信号：

- 企业架构分层
- 业务层 / 应用层 / 技术层
- 希望按正式企业架构语言表达

### Cloud / Network / Security

常见信号：

- 云厂商图标
- Kubernetes / VPC / Subnet / LB / API Gateway
- 网络拓扑、交换机、防火墙、零信任
- 安全分区、认证、审计、加密链路

## 表达原则

- 正式图法的语义正确优先于画面花哨
- 图标和 stencil 是辅助识别，不是装饰噱头
- 如果正式图法过于技术化，交付时补一句人话解释
- 如果需要向老板汇报，建议同时提供一个更易读的总览图

## 交付要求

使用正式图法时，交付说明里要明确：

- 采用了哪种图法
- 这张图主要表达什么
- 对非专业读者最该看哪一层或哪一条主线

如果当前图型比较典型，建议按需读取 `references/formal/examples/` 下的 few-shot 示例作为语法和结构锚点。

## 不要误判

- 不要因为用户说“流程”就默认 BPMN
- 不要因为用户说“架构图”就默认 ArchiMate
- 不要因为用户说“网络”就默认需要 Cisco 级拓扑细节

先判断用户要的是：

- `正式规范`
- 还是 `汇报表达`

如果主要目标是好讲清楚，而不是规范审阅，可以继续走自由图型。
