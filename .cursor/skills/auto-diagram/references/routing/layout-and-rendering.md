# Layout And Rendering

布局选择优先于视觉风格。
但布局判断发生在 backend routing 之后：先决定是否需要正式图法，再决定自由布局骨架。

这里的“布局”是信息骨架，不是固定模板。
不要把下面这些类别理解成可直接套用的现成画面，而要理解成几种常见叙事结构。

## 默认布局优先级

- 分层豆腐块
- 总线型
- 左右依赖
- 矩阵
- 树形
- 泳道
- 圆环
- 自由连线

## 选择口诀

`内容类型 -> 关系主轴 -> 信息密度 -> 汇报对象 -> 风险点 -> 布局骨架 -> 视觉风格`

补充判断：

- 先问“这张图最想让人按什么顺序理解”
- 再问“哪种骨架最少遮挡、最少绕线、最少压字”
- 再问“画布有没有被有效吃满，是否存在某一侧明显空跑带”
- 再问“复杂长边是否更适合用颜色分层，而不是继续堆拐弯”
- 再问“这个骨架在什么画幅里最自然”
- 最后才决定视觉风格

如果内容变了，就应当重新长出新的几何结构，而不是回忆上一次的版式照搬。

## 适配建议

### 分层豆腐块

适合：

- 标准技术架构图
- 平台分层图
- 要求稳定、整齐、汇报友好的场景

### 总线型

适合：

- 主干明确、支路较多的系统图
- 数据供给、共享底座、共用中台

### 左右依赖

适合：

- 上下游调用
- 因果关系
- 主链路需要一眼看清

### 矩阵

适合：

- 分类交叉
- 能力和场景的映射
- 对比型内容

### 泳道

适合：

- 明确阶段流程
- 角色职责流转

不适合：

- 静态组件依赖图
- 标题列和节点会明显抢空间的图
- 只是因为“流程图常见”就机械套用的场景

### 圆环 / 自由连线

只在内容真的适合时用。对向上汇报而言，它们默认不是首选。

## 渲染策略

- 默认：纯 SVG 主图
- 可选：HTML 包装页，仅用于背景、标题舞台、侧栏说明
- 如果任务被路由到 Mermaid / Graphviz / PlantUML，就遵守对应后端 contract
- 如果问题本质上是几何关系或遮挡问题，必须回到 SVG 坐标层解决
- 如果复杂反馈箭头已经严重拉高绕线成本，允许显式使用 `under-node` 箭头主干加颜色分层；但这只适用于箭头，不适用于文字、标签或说明卡

## Theme Pack Strategy

- `theme pack` 在这里属于视觉层，不属于骨架层
- 推荐判断顺序：
  - 先锁内容类型
  - 再锁关系主轴和布局骨架
  - 再决定当前任务更适合哪种视觉方向
  - 最后判断是命中内置主题包、走参考图学习，还是自由生成风格
- 如果已经命中主题包，允许继续保留当前任务的 `visual_style` 摘要作为轻量覆盖
- 如果主题包和当前骨架冲突，优先保住骨架，不要为了 pack 强行改布局
- 正式图法任务可以只轻量借用 theme token，不要强行套完整页面壳子

## 字体策略

- 默认排版走 CJK 友好的 sans-serif 字体栈：`PingFang SC` -> `Microsoft YaHei` -> `Hiragino Sans GB` -> `Noto Sans CJK SC` / `Noto Sans SC` / `Source Han Sans SC` -> 常见 Web sans-serif
- 标题、正文、注释、图例、边标签默认统一在同一套无衬线家族内，不要无故混搭 serif
- 如果参考图用了衬线体，也不要盲目复刻；先判断它是否真的属于用户必须保留的品牌规范
- 非 SVG 后端如果无法严格指定整条字体栈，也要尽量保持“清晰、投屏友好、CJK 友好、无衬线”的方向

## 画布比例判断

- 默认画幅是 `16:9`
- 只有当内容骨架、阅读方向或密度压力明显不适合 `16:9` 时，才主动推荐其他比例
- 先判断布局骨架，再判断比例；不要先拍脑袋选一个比例，再逼内容去适配
- 纵向层级深、上下分区重、说明卡较多时，优先考虑 `4:3` 或 `3:2`
- 矩阵、象限、对称关系、中心辐射型内容，优先考虑 `1:1`
- 移动端长图、海报型说明图、长链路纵向流程，优先考虑 `4:5` 或 `9:16`
- 如果用户已经明确给出比例，优先适配这个比例，并把布局往这个画幅里收敛
- 如果用户给的比例不理想，也只能提示风险和替代建议；不要未经确认就自行改比例
- 一旦草稿阶段确认了比例，后续正式渲染和交付都要沿用同一比例

## 布局锁定后的下一步

- 布局骨架一旦确定，不要直接进入正式渲染；先产出一版能看懂最终画面的草稿图
- 草稿图重点确认的是分区、阅读顺序、主链路、强调关系和画布比例，不是像素细节
- 草稿图里的低保真线框本身就要体现当前画幅；默认 `16:9` 时，草稿外形必须明显横向展开，而不是竖长堆叠
- 草稿图被确认后，再进入具体后端 contract 和正式出图

## 反模板提醒

- 不维护“模板库思维”
- 不根据过去成图直接复刻新图
- 允许复用的是判断方法，不是成品版式
