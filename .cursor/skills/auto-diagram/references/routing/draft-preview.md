# Draft Preview

这一阶段发生在 unified spec、图型和布局骨架都已锁定之后，但在正式 SVG 或其他重渲染开始之前。

目标不是提前交正式图，而是用一版低保真草稿，快速让用户确认“最后画面大概长什么样”。

## 这一阶段要完成什么

- 输出一版足够快、足够像最终画面的草稿图
- 推荐最适合最终 SVG 导出的画面比例和画布尺寸
- 让用户确认主结构、阅读路径、分区、重点强调和信息密度
- 把草稿图阶段确认的比例锁定到最终渲染
- 如果用户提出修改，先吸收修改并重出草稿，再进入正式渲染
- 只有草稿图被确认后，才进入 backend contract 和正式成图

## 草稿图的默认形式

- 默认使用低保真线框、ASCII / Markdown 框图、极简骨架图或其他快速表达方式
- 草稿图必须让用户看出标题区、分区、主节点、主链路、重点说明卡的大致落位
- 可以保留最终图的布局方向、视觉气质和阅读顺序，但不要提前做精修装饰、像素级对齐或完整 SVG 细节
- 如果用户给了参考图，草稿图只吸收其构图和风格线索，不要直接复刻原图文案

## 草稿外形与比例一致性

- 草稿图不只是在文字里声明比例；草稿本身的外轮廓和分区铺排，必须让人一眼看出当前画幅的大致感觉
- 如果当前推荐或锁定的是 `16:9`，草稿整体必须明显横向展开；不要输出竖长堆叠的长条草稿后再口头声称它是 `16:9`
- 如果当前推荐或锁定的是其他比例，草稿也必须优先保住该比例的宽高倾向；不要把所有比例都画成同一种长卷轴
- 默认优先级是：先保比例感，再保主结构，再保正文细节；比例感失真时，这轮草稿视为不合格
- 如果内容很多，优先扩大 ASCII / Markdown 草稿的整体宽度，或把卡片正文压缩为标题、短标签、占位符；不要为了塞满正文把草稿拉成长页
- 当聊天窗口或可读性限制不允许同时保留比例和全部正文时，只展示标题区、分区名、主节点、主链路和关键说明卡标题即可；细节留到 `🔍 本轮确认重点`、`⚠️ 仍待定稿` 或下一轮正式渲染
- 如果在既定比例内怎么排都明显拥挤，先重排主次区块、降低草稿密度，必要时明确提示比例风险；不要直接交一个比例失真的草稿

## `16:9` 草稿参考骨架

推荐像下面这样先把横向画幅站住，再逐步补信息：

```text
+----------------------------------------------------------------------------------+
| 标题区：一句主结论 / 副标题 / 读者标记                                               |
+--------------------------+-----------------------------------+-------------------+
| 左区：背景 / 输入         | 中区：主平台 / 主流程 / 主引擎      | 右区：输出 / 价值    |
| - 模块 A                 | - 主节点 A -> B -> C               | - 结果 1            |
| - 模块 B                 | - 关键链路 1 / 2                   | - 结果 2            |
| - 风险 / 约束            | - 说明卡 / 强调点                  | - 指标 / 收益        |
+--------------------------+-----------------------------------+-------------------+
| 底部说明区：图例 / 假设 / 下一阶段                                                   |
+----------------------------------------------------------------------------------+
```

高密度内容时，先降到结构级，不要为了塞正文把宽图画成长条：

```text
+----------------------------------------------------------------------------------+
| 标题区：XX 平台升级蓝图                                                            |
+--------------------+---------------------+---------------------+-----------------+
| 接入层             | 编排层              | 执行层              | 经营层          |
| [渠道] [API]       | [路由] [策略]       | [Agent] [Workflow]  | [指标] [报表]   |
| [数据源] [权限]    | [治理] [审计]       | [工具] [知识库]     | [运营] [反馈]   |
+--------------------+---------------------+---------------------+-----------------+
| 关键链路：接入 -> 编排 -> 执行 -> 经营      说明卡：风险 / 节奏 / owner               |
+----------------------------------------------------------------------------------+
```

反例信号：

- 草稿明显更高而不是更宽，但仍声称是 `16:9`
- 每个框里塞满整段正文，导致画面被迫纵向拉长
- 主结构只剩线性堆叠，看不出横向分区和阅读路径

## 比例推荐纪律

- 默认推荐 `16:9`，对应导出尺寸可优先用 `1920x1080`
- 如果内容明显更高、更方、更窄或更适合纵向阅读，就不要硬保 `16:9`；必须主动推荐更合适的比例和一组画布尺寸
- 如果用户已经明确给出比例，优先把该比例视为锁定条件；草稿图先按这个比例组织，最终渲染也必须保持同样比例
- 如果用户给的比例会让内容明显拥挤，先在同一比例内重排布局、调密度、拆主次区块；不要未经确认就偷偷改回 `16:9`
- 只有在用户指定比例已经严重伤害主叙事时，才允许明确提示风险并建议换比例；在用户改口前，仍应尽量按原比例推进

## 推荐比例的常见判断

- `16:9 / 1920x1080`：标准汇报型总览图、平台分层图、左右主链路图
- `4:3 / 1600x1200`：纵向层级更深、上下分区更重、标题区和说明区占比更高的图
- `3:2 / 1800x1200`：介于横向汇报和纵向承载之间，需要更多纵深但不想太方的图
- `1:1 / 1400x1400`：矩阵图、象限图、中心辐射图、强对称关系图
- `9:16 / 1080x1920` 或 `4:5 / 1200x1500`：移动端展示、海报式长图、纵向链路显著长于横向展开的图

这些是推荐起点，不是模板库。真正决定比例的仍然是内容骨架、阅读方向和密度压力。

## 必须出现的回执

- `🖼️ 草稿图`
- `📐 比例建议`
- `🧠 构图结论`
- `🔍 本轮确认重点`
- `⚠️ 仍待定稿`

## 默认确认菜单

```text
📍 当前: 草稿图已生成，主结构和阅读路径已可见
📌 下一步:
[1] 确认草稿图 - 进入正式渲染
[2] 提修改意见 - 我先吸收修改并重出草稿
[3] 回退结构 - 调整图型 / 分组 / 主叙事
[4] 切换导出比例 - 改画幅后重出草稿
[0] 暂停 - 先不继续
```

规则：

- `[1]` 只在草稿图已经覆盖主结构、主链路和重点区块时才能出现
- `[2]` 命中后，先总结修改吸收点，再重出新草稿，不要跳过草稿直接改正式图
- `[3]` 只在用户修改已经影响图型、布局骨架或核心叙事时使用
- `[4]` 适用于用户想保留同一内容但切换画幅；切换后要重出草稿，并把新比例同步进 unified spec
- 如果只缺一个事实，可以先补一个事实，再重出草稿；不要把简单补充升级成大段追问

## 迭代纪律

- 每轮草稿都要明确哪些部分已锁定、哪些部分仍是推断
- 每轮草稿都要明确当前使用或推荐的 SVG 比例、画布尺寸，以及它来自默认值、你的推荐还是用户锁定
- 每轮草稿都要明确当前风格来源：内置主题包、自定义风格，还是参考图学习
- 每轮草稿都要自检：去掉 `📐 比例建议` 文字后，用户是否仍能从草稿外形看出当前画幅倾向；如果不能，先重画草稿再发
- 用户没有明确确认前，不要开始正式 SVG 精修、质量脚本和导出
- 如果修改只影响文案轻重、局部增删、强调顺序，直接重出草稿即可
- 如果用户修改了比例要求，先在同一轮草稿里消化比例变化，再进入正式渲染
- 如果修改已经改变 diagram family、layout family 或 formal / informal 路径，回到 routing 或 intake 重判

## 正式图法 / 非 SVG 的处理

- 如果主任务是正式图法，但仍需要一张好讲的主图，草稿图优先预演总览图的构图
- 如果任务是 formal-only 且布局选择很少，草稿图可以退化为结构草案或分区线框，但仍要在重渲染前完成确认
- 草稿图阶段确认的是”画面与叙事方向 + 比例选择”，不是最终语法正确性；语法和像素质量留到后端与质量阶段

## 非交互模式

当 prompt 已预填全部 brainstorm 参数并要求”直接出图”时，草稿确认阶段自动通过：

- 仍然输出草稿图、比例建议和构图结论
- 但不弹出确认菜单，不等待用户回复
- 直接进入正式渲染、质量检查和交付
- 如果草稿阶段发现明显的结构冲突，仍然在回执中标注风险，但不阻塞流程
