# Brainstorm Mode

所有 `auto-diagram` 任务都必须先经过一轮强制 brainstorm。

这不是“信息不足时才使用”的可选步骤，而是固定入口闸门。

交互格式统一遵守 `references/shared/interaction-contract.md`。

## 目标

在开始画图前，先把下面这些问题锁死：

- 这张图到底是给谁看的
- 这张图要解决什么表达问题
- 这张图最重要的一句话是什么
- 这张图是更偏汇报、评审还是执行
- 这张图需要什么风格、是否命中现有主题包、以及什么密度
- 这张图是否需要正式图法

## 禁止行为

- 禁止看到用户描述很长，就直接开始画图
- 禁止只回一句“信息足够，我直接做”
- 禁止只问开放大题，让用户重新写一遍需求
- 禁止在 brainstorm 完成前直接选模板、选后端、写图稿

## 必须产出的四段

第一轮必须给出：

- `🧾 已知信息回执`
- `❓ 待确认点`
- `✨ 增强建议`
- `🧭 推荐默认方向`

## 最少确认点要求

- 至少 4 个
- 至少 2 个影响结构
- 至少 1 个影响视觉风格
- 至少 1 个影响汇报效果或阅读路径

如果用户输入再详细，也必须主动找出这些点中的一部分进行确认。

## 必问维度

每次 brainstorm 都必须覆盖这些维度：

- `audience`：主要读者是谁，老板、评审、客户、团队、合作方还是执行同学
- `purpose`：是为汇报、说服、争取资源、对齐认知、讲清结构，还是指导落地
- `core_message`：对方只能记住一句话时，希望记住什么
- `story_axis`：更偏讲结构、讲流程、讲差异、讲方案、讲路径、讲问题归因中的哪一种
- `style`：更偏克制商务、科技氛围、温和中性、强对比、极简还是其他
- `theme_strategy`：更适合现有主题包、参考图学习、还是自由生成风格
- `density`：更偏老板版、评审版、执行版，还是需要一个中间态
- `formal_notation`：是否需要用 UML、BPMN、ArchiMate、Cloud、Network、Security 等正式图法
- `constraints`：是否有必须出现、必须不出现、必须弱化的模块或文案

## 提问方式

不要问大而空的问题。
优先给用户锁定式确认，而不是开放作文题。

推荐形式：

- “这张图更偏老板汇报还是团队执行？”
- “你是想突出系统分层，还是突出主链路？”
- “视觉上更偏克制商务，还是偏科技氛围？”
- “我可以推荐一个现有主题包，你也可以直接说一个你想要的风格词。”
- “这张图要不要用正式图法，还是以好讲清楚为主？”

如果需要用户在几个明确方向中选一个，优先用菜单，不要让用户重新写长段需求。

## 当用户说“你自己定”

不能跳过。

要改成：

- 给出你的默认锁定建议
- 明确哪些是你的判断
- 请用户做一次确认或轻量修正

例如：

- `我建议先按“老板汇报 + 讲结构主线 + 默认日间蓝图主题包 + 中密信息”来做，请你确认是否可行`

## 主题包推荐纪律

- 如果当前内容明显适配现有主题包，可以推荐 **1 个最适合的主题包**
- 推荐主题包时，同时保留 **1 句当前任务自己的视觉方向**，不要只说 pack 名称
- 不要默认把所有主题包逐个列出来
- 推荐主题包时，顺手提示：
  - `我们现在有 X 个主题包可选；如果你想看全量，我可以继续展开`
- 这里的 `X` 默认用 `python3 scripts/theme/list-theme-packs.py --count` 获取
- 如果用户自己说了一个风格词，例如“恬静风格”“工业感”“杂志感”，优先跟随用户，按自由风格生成路线走，不要硬拉回内置主题包
- 如果用户给了参考图并说“按这个风格来”，优先走参考图学习，不要拿默认主题包覆盖

推荐收口格式：

```text
📍 当前: 第一轮 brainstorm 已完成
📌 下一步:
[1] 确认推荐方向 - 直接按默认版本进入草稿图
[2] 补充信息 - 再补 1-2 个会影响结构的点
[3] 调整风格 - 改视觉方向、主题包或信息密度
[0] 暂停 - 先不继续
```

## 增强型确认点

即便没有硬性歧义，也要主动找“还能把图做得更好”的点。

优先从这些角度找：

- 当前主结论是否还能再尖锐一点
- 阅读路径是否足够清楚
- 是否有应当删掉的次要信息
- 是否有应当强调的对比关系
- 是否需要多版本密度建议
- 是否有更适合当前受众的视觉方向

## 结束条件

只有当下面这些信息已经被用户确认或默许，brainstorm 才算结束：

- audience
- purpose
- core_message
- story_axis
- style
- theme_strategy
- density
- formal_notation_required
- must_show / must_not_show
