# Brainstorm Templates

这些模板不是为了把用户带进问卷，而是为了让第一轮澄清稳定、高质量、可执行。

交互格式统一遵守 `references/shared/interaction-contract.md`。

## 默认输出骨架

第一轮建议按下面四段输出：

```text
🧾 已知信息回执
- ...

❓ 待确认点
1. ...
2. ...
3. ...
4. ...

✨ 增强建议
- ...
- ...

🧭 推荐默认方向
- ...
```

## 标准提问模板

### 模板 A：汇报型大图

适用于：

- 老板汇报
- 平台总览
- 现状到目标态
- 架构升级方案

推荐确认点：

1. 这张图主要是给老板看、给评审看，还是给执行团队看
2. 你更想突出“分层结构”还是“从问题到方案的主链路”
3. 视觉上更偏克制商务，还是偏科技氛围
4. 这张图是要一页讲完，还是允许总览图加一页展开图
5. 有没有必须弱化或不要放进主图的细节

### 模板 B：流程 / 协作图

适用于：

- 流程图
- 角色协作
- 审批流

推荐确认点：

1. 你是要讲清“阶段流转”，还是讲清“角色责任”
2. 这张图是偏业务说明，还是要接近正式流程规范
3. 是否需要突出异常分支 / 决策节点
4. 读者更关心全流程，还是更关心关键卡点
5. 视觉上更偏简洁文档风，还是偏汇报风

### 模板 C：关系 / 依赖图

适用于：

- 模块依赖
- 数据流向
- 系统关系图

推荐确认点：

1. 你更想强调“主链路”，还是“全量依赖关系”
2. 这张图是偏说明关系，还是偏用于排查和评审
3. 要不要把弱依赖也画出来
4. 是更适合一张高密关系图，还是一张总览图加一张细节图
5. 视觉上是偏理性克制，还是允许更强分区感

### 模板 D：正式图法

适用于：

- UML
- BPMN
- ArchiMate
- Cloud / Network / Security

推荐确认点：

1. 你是要正式规范表达，还是更强调“能拿去讲”
2. 是否需要行业标准图标 / provider icons
3. 读者是专业技术同学，还是非专业决策者
4. 这张图要不要同时补一张更易读的汇报总览图
5. 有没有必须遵守的术语、图例、命名方式

## 当用户输入已经很完整时

不要重复问用户已经说过的话。
要改成“锁定式复述 + 精准增量确认”。

推荐形式：

```text
🧾 已知信息回执
- 读者：...
- 用途：...
- 主结论：...

❓ 待确认点
1. ...
2. ...
3. ...
4. ...
```

## 当用户很模糊时

优先给 2 到 4 个合理方向让他选，不要让他重新写一大段。

例如：

- `如果这张图主要拿去向老板汇报，我建议做“分层总览 + 主链路”`
- `如果这张图主要给执行团队落地，我建议做“流程/职责泳道”`

## Brainstorm 完成标记

满足下面任一条件，才能继续：

- 用户逐项确认了关键点
- 用户确认“按你推荐的默认方向做”
- 用户对默认项做了少量修正，剩余部分默许
