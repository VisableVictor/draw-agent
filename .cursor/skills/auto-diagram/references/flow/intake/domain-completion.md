# Domain Completion

当用户给出的内容不完整，但图的方向明确时，不要停在“信息不足”。优先像对应领域的专家同事一样，补全一个合理的结构草案。

## 补全原则

- 先补结构，再补措辞
- 先补主模块，再补细枝末节
- 先补主链路，再补边角说明
- 补全结果要显式标出哪些是 `推断`

## 常见领域补全思路

### 技术架构 / 系统图

优先补：

- 用户入口 / 调用入口
- 控制面 / 调度层
- 核心执行层
- 数据 / 存储 / 底座
- 监控、治理、权限、运维等横切层

### 平台 / 能力地图

优先补：

- 业务目标
- 核心能力层
- 平台底座层
- 数据、策略、治理支撑
- 指标或结果映射

### 流程 / 协作图

优先补：

- 起点
- 关键阶段
- 责任角色
- 决策节点
- 异常分支
- 最终输出

### 现状到目标态

优先补：

- 当前问题
- 现状结构
- 差距
- 目标结构
- 过渡动作
- 风险和依赖

## 什么时候必须确认

只有当下面这些差异会改变整张图的叙事时，才需要用户确认：

- 图到底是讲“流程”还是讲“架构”
- 图的核心对象到底是谁
- 需要强调的主结论完全不同
- 两种补全方案会导致完全不同的阅读顺序

否则先给用户一个结构化补全版本，再请用户拍板。
