# Delivery Templates

这些模板不是为了让回答变僵硬，而是为了让成图交付稳定具备“图 + 讲法 + 风险说明”。

## 模板 A：普通图交付

适用于：

- 汇报型总览图
- 能力图
- 流程图
- 关系图

推荐输出骨架：

```text
✅ 当前产出
- ...
- 比例：...
- 风格：...

🧠 一句主结论
- ...

🗺️ 推荐阅读路径
1. ...
2. ...
3. ...

🗣️ 30 秒讲法
- ...

⚠️ 假设说明
- ...
```

## 模板 B：正式图法交付

适用于：

- UML
- BPMN
- ArchiMate
- Cloud
- Network
- Security
- Data Analytics
- IoT

推荐输出骨架：

```text
✅ 当前产出
- ...
- 比例：...
- 风格：...

📘 图法说明
- 本图采用：...
- 主要表达：...

👀 非专业读者优先看
- 先看 ...
- 再看 ...

🗣️ 30 秒讲法
- ...

⚠️ 风险 / 假设
- ...
```

## 模板 C：双图交付

适用于：

- 既要正式规范
- 又要向老板或评审讲清大局

推荐输出骨架：

```text
✅ 当前产出
- 图 1：汇报总览图
- 图 2：正式图法图
- 比例：...
- 风格：...

🗺️ 怎么配合使用
1. 先用总览图讲主结论
2. 再用正式图解释细节和规范关系

🗣️ 30 秒讲法
- ...

🔍 追问准备
- ...
```

## 模板 D：Brainstorm 收口

适用于：

- 第一轮澄清结束，准备进入草稿图阶段

推荐输出骨架：

```text
🧭 我先按下面这个方向锁定：
- 读者：...
- 用途：...
- 主结论：...
- 图型：...
- 主题包：...
- 风格：...
- 密度：...

如果你没有异议，我就先按这个版本产出草稿图，等你确认画面后再进入正式渲染。
```

## 模板 E：图片完成后的 PPTX 选择

适用于：

- 主图已经生成完成
- 用户还没有明确说要不要 `pptx`

推荐输出骨架：

```text
✅ 当前产出
- SVG：...
- PNG：...
- 比例：...
- 风格：...

📍 当前: 图片已生成并通过质量检查
📌 下一步:
[1] 返回图片 - 直接交付 SVG / PNG
[2] 生成 PPTX - 把当前成图打包成单页汇报稿
[3] 生成可编辑 PPTX - 仅限当前 auto-diagram 受控 SVG
[4] 沉淀为主题包 - 仅当本次风格来自参考图学习
[0] 暂不导出 - 先看图再决定
```

## 模板 F：参考图风格沉淀

适用于：

- 本次任务来自参考图学习
- 最终大图已经完成
- 当前风格值得后续复用

推荐输出骨架：

```text
✅ 当前产出
- SVG：...
- PNG：...
- 比例：...
- 风格：参考图学习结果

📍 当前: 本次风格已经落成可复用画面
📌 下一步:
[1] 保持一次性风格 - 本次交付到这里即可
[2] 沉淀为主题包 - 以后都可以作为可选风格
[0] 暂不处理 - 先只收图
```

## 模板 G：沉淀执行回执

适用于：

- 用户已经确认沉淀为主题包
- AI 已完成 base pack 判断与脚本执行

推荐输出骨架：

```text
🧩 主题包沉淀
- 名称：...
- 基于：...
- 风格摘要：...
- 预览：...

✅ 当前产出
- 新主题包：...
- 当前主题包总数：...

🧠 后续如何用
- 下次你可以直接说“用这个主题包风格”
- 如果内容相近，我在 brainstorm 阶段也可能主动推荐它
```

## 使用纪律

- 模板服务表达，不要让回答机械化
- 有正式图法时，一定要把“图法说明”和“非专业读者优先看什么”补上
- 有双图策略时，不要只说“我给了两张图”，要说明两张图怎么配合讲
