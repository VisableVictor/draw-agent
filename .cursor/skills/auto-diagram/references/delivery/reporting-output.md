# Reporting Output

这个 skill 的目标不是只给图文件，而是给“能拿去讲”的成品。

交互格式统一遵守 `references/shared/interaction-contract.md`。

## 最低交付

- `✅ 当前产出`
- `导出比例 / 画布尺寸`
- `当前风格 / 主题来源`
- `🧠 一句主结论`
- `🗺️ 推荐阅读顺序`（作为对话文字返回，不放进主图）

默认不要把这些内部动作直接告诉用户：

- `正在执行 stabilize / finalize`

这些都属于内部后处理。对外只需要交付结果，不需要交付脚本过程。
另外，交付图不注入可见水印；禁止手写或手工追加水印、logo、署名或额外品牌页脚。

## 汇报增强交付

在下面场景里，主动给出讲法：

- 用户明确说要汇报
- 图比较复杂
- 图里有多层结构或多条主线

建议补充：

- `30秒讲法`
- `2分钟讲法`
- `最可能被追问的点`

如果走的是正式图法，还应补一句：

- `这张图采用了什么正式图法`
- `非专业读者优先看哪一层或哪一条主线`

这些内容的默认承载方式：

- 返回在对话正文里
- 不进入 SVG 主图
- 不做成图内“讲稿卡片”“阅读提示卡”“汇报备注框”

只有当用户明确要求“把讲解一起做进图里”时，才允许作为辅助说明层出现。

## 图片完成后的 PPTX 选择

当 `.svg` / `.png` 已生成且主图通过检查后：

- 如果用户此前已经明确要求 `pptx`，直接导出
- 如果用户此前没有明确要求 `pptx`，给一次明确选择

推荐菜单：

```text
📍 当前: 图片已生成并通过质量检查
📌 下一步:
[1] 返回图片 - 直接交付 SVG / PNG
[2] 生成 PPTX - 稳定单页汇报稿（图片版）
[3] 生成可编辑 PPTX - 仅限当前 auto-diagram 受控 SVG
[4] 沉淀为主题包 - 仅当本次风格来自参考图学习且值得复用
[0] 暂不导出 - 先看图再决定
```

可编辑 PPTX 只接受已经执行 `scripts/stabilize-svg.cjs` 或 `scripts/finalize-svg.cjs` 的受控 SVG；如果还没写入 metadata 状态封印，先在内部静默稳定化，再导出，不需要把这一步单独播报给用户。

## 参考图风格沉淀

只在下面条件同时成立时追加主题包沉淀选项：

- 当前任务来自参考图学习
- 最终大图已经交付
- 本次风格具有明显复用价值

如果用户确认沉淀，再补 1 个事实即可：

- 主题包名称

如果用户不想起名，可以给一个短推荐名。

确认后，优先执行：

```bash
python3 scripts/theme/promote-reference-style.py ...
```

## 密度分档

必要时给出三个版本建议：

- `老板版`：结论优先，信息压缩
- `评审版`：保留关键结构与依赖
- `执行版`：补齐模块、链路、说明

当正式图法和汇报表达冲突时，优先建议：

- `一张正式图 + 一张汇报总览图`

## 常见收束方式

- 一句话标题先讲结论，不只讲主题
- 图例尽量短；阅读路径放在对话里讲
- 如果一页过载，主动建议拆成总览图 + 局部展开图
- 面向老板或评审的主图，默认只保留理解结构所必须的标题、分组、图例、必要注释；不要把小抄写进图里
