# Backend Matrix

用户只和 `auto-diagram` 对话，不需要自己选择后端。

后端选择是 skill 的内部责任。

如果需要把路由判断回执给用户，建议使用 `🛠️ 生成计划` 作为阶段标题。

## 路由顺序

按下面顺序判断：

`表达目标 -> 是否要求正式图法 -> 关系复杂度 -> 信息密度 -> 汇报对象 -> 视觉要求 -> 交付后端`

## 默认后端

### SVG-first

优先用于：

- 汇报级总览图
- 大图
- 能力地图
- 现状到目标态
- 平台架构总图
- 需要参考图风格迁移的任务
- 正式图法不足以支撑汇报表达的场景

### Mermaid

优先用于：

- 简单流程图
- 简单时序图
- 轻量状态流转图
- 轻量链路图
- 用户本身就在 Markdown / 文档里使用该图

### Graphviz

优先用于：

- 高边密度依赖图
- 模块关系图
- 包关系图
- 调用关系图
- 多层级关系图

### PlantUML

优先用于：

- UML
- BPMN
- ArchiMate
- Cloud
- Network
- Security
- Data Analytics
- IoT
- 正式部署图

## 两张图策略

当下面两类目标同时存在时，可以默认建议两张图：

- 既要正式规范
- 又要一眼讲清大局

推荐组合：

- `SVG 总览图 + PlantUML 正式图`
- `SVG 汇报图 + Graphviz 关系图`

## 路由输出

进入任何后端前，都要在内部推理中至少明确：

- 为什么选这个后端
- 为什么不用其他后端
- 这个后端的主要风险是什么
- 如果失败，fallback 到什么后端
