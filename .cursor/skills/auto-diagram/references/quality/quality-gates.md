# Quality Gates

没过这些闸门，就不要交付。

## 必过项

- 任意两个主节点不得重叠
- 任意主节点、说明卡、摘要卡之间也不得互相遮挡；即使不重叠，局部安全 gutter 过小也视为未通过
- 任意节点文字不得突破内 padding 安全区
- 任意说明卡、摘要卡、侧注卡的文字也不得突破卡片边界
- 任意正文长句如果宽度已接近容器上限，却仍未显式折行，也视为未通过
- 任意文字块如果实际落点导致底部贴边、顶部贴边，或上下留白明显失衡，也视为未通过
- 任意砖块如果新增文案后仍维持原尺寸，导致只能靠压缩留白才能放下文字，也视为未通过；应增宽或增高容器
- 任意带边框的 chip / mini card，即使没有显式写成 `ad-node`，也必须通过最小推荐尺寸检查；不能因为是匿名 `rect + text` 就逃过质检
- 任意页面主标题、副标题、页脚 legend 都不得被主节点、说明卡、分组、主舞台、箭头或边标签侵入
- 任意页面主标题、副标题、页脚 legend 都必须保留页面 gutter，不得超出版心安全区
- 任意伪水印、手工署名、`auto-diagram 生成`、`Generated by auto-diagram` 等额外品牌文本都视为未通过；交付图不允许水印、署名或额外品牌标记
- 任意手写、手工绘制、手工粘贴、模型直接生成或旧脚本残留的水印都视为未通过；稳定化脚本只允许写入 metadata 状态封印，不注入可见水印
- 任意箭头不得压住标题、正文、泳道标题或图例文案
- 任意箭头主干不得穿过主节点砖块内部；只允许在砖块外部绕行，或从边缘锚点贴边进入/离开
- 任意箭头主干不得沿 node / group / stage 边框长距离重叠；只允许在锚点处短暂接边
- 任意边标签不得贴节点边缘或箭头端点
- 任意边标签不得互相压住，也不得压在主节点、说明卡、摘要卡上
- 同层节点要整齐，同列节点要整齐
- 多箭头汇聚时，箭头头部不能互相覆盖
- 图例语义必须与主图一致
- 属于某个分组的节点不得越出分组容器边界
- 主节点不得越出主舞台安全区
- 即使 node 没显式写 `data-group-id` / `data-stage-id`，只要视觉中心明显落在某个 group / stage 内，也要按该母容器检查越界
- 任意边标签不得压在分组标题区
- 任意节点或说明卡也不得侵入分组标题区
- 任意顶部摘要卡、说明卡如果存在，也不得压进页面标题块；只能作为 header chrome 的旁侧补充，而不是盖住标题
- 任意主舞台或分组，如果某一侧出现异常大的空白带，导致内容包络明显没有把画布或母容器用起来，也视为未通过
- 任意子区域如果距离母区域边缘过远，形成一眼可见的“空跑带”，也视为未通过；应扩展子区域、重排节点或缩小母容器
- 任意主舞台如果相对整个 SVG 画布本身就明显偏左、偏右、偏上或偏下，导致与页面外沿形成一侧过大的空带，也视为未通过
- 即使主舞台内部已被孩子填满，如果整张图的内容包络相对整个 SVG 仍明显没有吃满宽度或边缘失衡，也视为未通过
- 如果任务属于正式图法，图法语义和关系方向必须正确
- 如果任务走的是非 SVG 后端，也必须检查是否符合该后端 contract

## 视觉规则

- 字号必须适合投屏，不要为了塞内容而牺牲可读性
- 高密信息图可以紧凑，但不能混乱
- 一眼就要看出主链路和分区
- 如果缩到 80%，主结构仍应清晰
- 如果一条线只能靠“压在砖块上”才能走通，说明布局骨架错了，必须重排，不得硬连
- 对复杂长反馈线、例外线、控制线，可以用颜色分层辅助识别，不必强求完全靠多次拐弯来区分
- 但只有显式标记为 `under-node` 的箭头主干，才允许走在节点下层并被节点砖块局部遮挡；这个例外不适用于文字、标签、说明卡、摘要卡或任何非箭头元素
- 如果一个文字卡片不能靠正常折行放进框内，说明尺寸或文案有问题，必须重排，不得直接溢出
- 如果画面在已确认比例下明显拥挤，优先重排或扩同比例画布；不要在质量阶段静默换成别的比例
- 如果画面某一侧留出大块无意义留白，优先推动内容重新分布到更均衡的画布范围，而不是默认保留那块空带
- 如果主舞台贴着一侧而离另一侧 SVG 外沿很远，说明问题已经升级到整张图的 page-level 构图失衡，不能只在母容器内部做局部微调
- 如果图里使用了多种边语义、明显不同的通道颜色或多种虚实线，应该提供 legend 或清楚的阅读提示；不要让用户靠猜
- 默认字体栈必须优先 `PingFang SC`，回退到 `Microsoft YaHei` 与常见 sans-serif；除非用户明确要求特殊风格，否则不要混入 serif

## 推荐校验顺序

1. 运行 `python3 scripts/quality/run-quality-preflight.py --stage hard <svg-file>`，进入 Q1 结构闸门并批量收集关键结构问题
2. Agent 按同轮汇总报告进入 Q2 关键修复，批量修复全部关键结构问题
3. 运行 `python3 scripts/quality/render-quality-preview.py <svg-file> --stage hard --round <n> --label after-repair`，向用户展示 `🖼️ 质量闸门 Q3/5｜效果预览`
4. 重跑 Q1 结构闸门；最多自动 3 轮，第 3 轮仍未清零时按交互协议让用户选择
5. Q1 结构闸门通过后，确认正式图法任务的图法语义与关系方向
6. 给出 hard-clean 预览链接，再让用户选择进入 Q4 视觉打磨，或直接接受当前版本进入导出
7. 若进入 Q4 视觉打磨，运行 `python3 scripts/quality/run-quality-preflight.py --stage soft <svg-file>`，批量收集可优化项 / 打磨建议
8. Agent 按同轮汇总报告批量处理关键打磨项
9. 运行 `python3 scripts/quality/render-quality-preview.py <svg-file> --stage soft --round <n> --label after-polish`，向用户展示当前 SVG / PNG 预览
10. 每轮视觉修改后运行 Q5 交付复核；若发现关键结构问题，回到 Q2 关键修复
11. Q4 视觉打磨最多自动 3 轮，第 3 轮后仍有 finding 时先展示 Q3 效果预览，再按交互协议让用户选择
12. 最近一次 Q1 结构闸门通过后，运行 `scripts/export/export-diagram.sh <svg-file> [png-width]` 导出 PNG
13. 目测检查 PNG 的文字边界、边距、箭头尺寸和投屏可读性
14. 确认图内没有把“30秒讲法 / 推荐阅读路径 / 汇报备注”塞成主图元素
15. 确认没有无意义的序号圆点、角标、装饰性编号

## 脚本用途

- `check-svg-attribution.py`：检查伪水印、重复品牌署名、`auto-diagram 生成`、旧水印几何残留等 unauthorized attribution / branding
- `lint-svg-diagram.py`：结构、marker、节点/说明卡重叠、极小 gutter、显式或推断母容器越界、标题区碰撞、边标签碰撞、箭头头部，以及 `under-node` 箭头之外的穿砖规则
- `check-svg-edge-clearance.py`：检查边线是否沿 node / group / stage 边框滑行，避免“看似没穿砖、但视觉上黏在边框上”的情况
- `check-svg-node-padding.py`：砖块文字的宽度、高度、实际落点、上下留白平衡，以及最小推荐砖块尺寸检查；支持 `--recommend`
- `check-svg-page-chrome.py`：页面标题、副标题、footer legend 的 gutter、header/footer 安全区、chrome 与主图碰撞，以及基础 page chrome 节奏
- `check-layout-rhythm.py`：对齐、间距、分组内边距、舞台重心、密度热点，以及“是否把画布 / 母容器用起来”的留白与外沿距离检查
- `check-visual-hierarchy.py`：主次层级、主链路显著性、主阅读方向、注释卡权重；默认优先看 `primary / sync / async / neutral` 通道，不把 `feedback / control / exception` 混进主阅读方向判断
- `check-svg-legend-semantics.py`：当存在多通道边色、虚实线或语义分层时，检查 legend 是否足以解释这些差异
- `review-diagram-quality.py`：把 soft warning / hint 转成内部修图动作，不直接给用户看
- `run-quality-preflight.py`：批量编排 hard / soft 检查，同阶段某个脚本失败时继续收集其他检查结果，并输出 compact report 供 Agent 批量修复；用户可见回执必须翻译成 Q 阶段语言
- `render-quality-preview.py`：为每轮 Q2 关键修复 / Q4 视觉打磨生成阶段性 SVG 快照，并尽量导出 PNG；Agent 必须把图片或链接展示给用户
- `export-diagram.sh`：Q1 结构闸门通过后的最终导出链路，串联 SVG 稳定化、导出前文本 auto-fit / safe grow、校验、PNG 导出前的 CSS 变量兼容化与导出
- 其他后端的语法正确性，需要由对应 backend contract 兜底

## 汇报洁癖规则

- 主图不是提词器
- 主图不是会议纪要
- 主图不是备注页
- 能放在对话说明里的内容，默认不要占用画面
- 没有表达增益的序号徽标，默认不要占用画面
