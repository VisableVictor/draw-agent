# 总流程

运行顺序：判断意图，识别场景，补齐信息，取素材，写场景 prompt，选择模型并填工具参数。

## 任务意图

先判断用户要做什么。

| 意图 | 处理方式 |
|------|----------|
| 新图生成 | 进入场景识别和生图流程 |
| 参考图生成 | 仅传用户明确要求参与本次生成的图，进入场景流程 |
| 图片编辑 | 仅传用户明确要求修改的图，prompt 写清修改要求 |
| 查询状态 | 不生图，只用 `generateUuid` 查状态 |
| 查询记录 ID | 不生图，只用 `generateUuid` 查 `recordId` |
| 保存素材库 | 先查 `recordId`，再保存 |

## 场景和信息

场景触发词和关键信息见 `scenes.md`。最多追问 1 轮，每轮最多 2 个问题。

## 信息不足

信息不全不等于不能出图。只有缺失会导致无法完成用户明确目标，或必须编造业务事实时才追问；其他情况直接省略相应模块或使用默认视觉表达。

| 类型 | 处理 |
|------|------|
| 缺主体/主题 | 追问，不调用生图工具 |
| 缺用户明确要展示的业务事实 | 追问，不编造时间、地点、数字、部门、承诺 |
| 缺场景模板中的某个模块，但用户未要求展示 | 不追问，省略该模块 |
| 缺风格/色彩/比例/尺寸 | 不追问，按场景默认值 |
| 缺平台/用途但不影响出图 | 不追问，按通用用途 |
| 用户说"随便"、"你看着办" | 不追问，使用合理默认值 |
| 本地图片作为编辑目标且无法上传 | 要求线上图片 URL |

各场景关键信息只维护在 `scenes.md` 和对应场景文件里，避免重复。

## 执行链路

以下链路是内部执行顺序，不要在用户可见回复里展开。

```
用户输入
  ↓
1. 扫描模型别名，锁定用户指定模型
  ↓
2. 判断任务意图
  ↓
3. 读取 `scenes.md` 识别场景，再进入对应 `scenes/*.md`
  ↓
4. 根据关键信息决定追问、省略模块或使用默认值，取场景默认尺寸和 Prompt 模块
  ↓
5. 调用素材库；按用户输入决定哪些用户图参与本次生成；本地图按 `image-upload.md` 用 `done-cli upload` 转成 URL；素材库有可用图时，由 agent 选最合适的一张追加到最后
  ↓
6. 有素材库参考图时直接写轻提示；无素材库参考图时按场景 Prompt 模块填入用户内容、输入图顺序和必要约束
  ↓
7. 读取 `routing-and-tools.md` 选择模型并填工具参数
  ↓
8. 工具要 `width/height` 就选合法宽高，工具要 `aspectRatio` 就选合适比例
  ↓
9. 调用工具并按 `polling-and-errors.md` 轮询
  ↓
10. 验收结果并输出图片与完整 prompt；用户要求时再输出工具参数
```

## Prompt 内置规则

任务一致性优先：prompt 必须保留用户原始目标、场景、核心信息和语气；不能把通知改成营销海报，不能把中性数据改成庆祝战报，不能添加用户没给的业务事实或承诺。

Prompt 是交付内容。默认展示完整 Prompt；工具参数、任务 ID 和排障细节只在用户要求时展示。

Prompt 组装顺序：

1. 保留用户原始主体、用途、文字、数据和语气。
2. 先判断是否使用素材库参考图。
3. 使用素材库参考图时，直接使用素材库参考图轻提示模式；只写用户原始需求、参考图角色、用户明确硬约束、无水印、无多余文字，然后跳到模型参数。
4. 不使用素材库参考图时，套用场景文件的 Prompt 模块。
5. 无素材库参考图时，用户缺风格/色彩/比例可只补视觉表达，不补业务事实。
6. 写入尺寸意图：方图、竖图、横图、长图、Banner、头像、壁纸等。
7. 最后加入文字准确、无水印、无多余文字等验收约束。

Prompt 骨架：

```text
场景/用途：{场景和投放位置}
主请求：{用户原始目标}
输入图：{按顺序说明图片角色；无图时省略}
主体/内容：{画面主体、业务内容、数据、流程或文案}
文字：{用户明确要求展示的原文；无文字需求时省略}
参考图：{素材库参考图角色；无素材库参考图时省略}
风格/媒介：{照片、插画、3D、信息图、办公视觉等}
构图/版式：{比例、信息层级、主体位置、留白和阅读路径}
光影/色彩/质感：{只补视觉表达，不补业务事实}
约束：{准确性、保持项、禁用项}
避免：{水印、多余文字、编造事实、与参考图冲突的内容}
```

骨架不是固定输出格式。场景文件只保留有用字段；缺失字段直接省略。用户描述已经具体时，只整理成清晰 prompt，不额外加角色、物体、品牌、口号、数据或剧情；用户描述很泛时，可以补充构图、媒介、光影、质感、阅读层级等有助于成图的视觉细节。

场景 Prompt 模块里的占位字段只填用户已提供、可从用户输入直接归纳、或不涉及业务事实的默认视觉表达。用户未提供的时间、地点、部门、数据、嘉宾、二维码、CTA、Logo、来源等字段，不保留占位符，不写"待补"，不编造内容，直接省略对应句子或模块。

### 图片参与模式

只有两类图片进入 `referenceImageUrls`：

1. 用户明确要求参与本次生成的图片：例如编辑目标、基于这张图、参考这张图、保持图中人物/IP/产品/Logo 等。
2. agent 从素材库中选中的一张素材图。

用户只是上传图片，但文字需求没有指向这张图时，不自动传入图片字段，不因为有附件就切换成图改图；继续按用户文字需求生成。

素材库图片不要求用户再提供输入图。即使素材历史 prompt 里写了"图1"、"图2"、"参考图"、"输入图"或类似依赖，也只代表历史生成上下文，不是本次使用该素材的前置条件。选中素材后，只传该素材自己的 `coverUrl`。

### 素材库参考图轻提示模式

素材库命中可用图片时，本次生图由素材库图辅助。素材库图的价值是作为真实参考图传给模型，不是让 agent 根据素材再写一段新画面。

使用素材库参考图时，工具仍然必须传 `prompt` 参数，但这个 `prompt` 只用于说明用户目标和素材库图角色，不再做场景扩写。

实际工具 prompt 必须按下面的轻提示写法组织：

```text
{用户原始需求}
参考图列表最后一张为素材库参考图，请基于用户输入参考该图生成。
不要照搬参考图中的旧文案、旧主题、旧数据或与用户输入冲突的内容。
{用户明确要求的文字、人物/IP/产品/Logo保持项；没有则省略}
无水印，无多余文字。
```

不要把素材 `backfillParams.prompt` 改写进生成 prompt；它只用于选图。不要在未读取图片内容时描述参考图细节。不要因为场景模板自动添加用户没说的画面元素或业务信息。

使用素材库参考图时，禁止再写这些内容：

```text
现在构建完整 prompt
根据 generic-image / event / banner 等场景 Prompt 模块
画面主题：...
风格：...
构图：...
光影：...
约束：...（除用户明确约束、无水印、无多余文字外）
```

## 输入图规则

- 用户明确要求参与本次生成的上传图或图片 URL，按原顺序传入。
- 用户没有要求使用的上传图，不进入 `referenceImageUrls`，不写进 prompt，不因为图片数量追问。
- 参考图字段只接受 `http://` 或 `https://` URL。本地文件或对话附件按 `image-upload.md` 优先用 `done-cli upload` 转成 URL。
- 普通参考图无法上传：不传参考图字段，并在 prompt 或输出说明中写明参考图已跳过。
- 编辑目标无法上传：停止生图，要求用户提供线上图片 URL。
- 用户要求人物一致、IP 做动作、产品展示、Logo 使用或图片编辑时，直接把保持项和变化项写进 prompt。
- 素材库是否使用由 agent 根据用户输入和素材库返回内容自行决定。
- 选中素材图作为素材库参考图追加到输入图最后。
- 有素材库参考图时，实际 prompt 正文只需标明"参考图列表最后一张为素材库参考图"，并说明基于用户输入参考该图生成。
- 如果没有实际读取图片内容，不要写"图中有..."或描述封面细节；素材 `backfillParams.prompt`、分类名、素材库名只用于选图，不用于扩写生成 prompt，也不能当作本次缺少输入图的理由。

素材库图只在用户明确要求"基于素材库这张图修改"时作为编辑目标；否则只能作为参考图。

输入图保持项写法：

| 用户要求 | Prompt 必须写入 |
|----------|----------------|
| 人物一致 / IP 做动作 | 保持用户图中人物或 IP 的外观、轮廓、五官、发型、服装和标识主特征一致，仅按需求改变动作、表情、场景或姿态 |
| 产品展示 | 保持产品外形、颜色、比例、材质和关键标识一致 |
| Logo 使用 | 保持 Logo 颜色、比例、形态和文字不变，不重绘不变形 |
| 图片编辑 | 保持未要求修改的主体、布局和文字，只修改用户指定部分 |

## 结果验收

- 图中文字、数据、时间地点必须和用户输入一致。
- 进入 `referenceImageUrls` 的用户图要被正确使用：人物不明显变脸，Logo 不变形，产品外形不乱改。
- 构图方向要匹配工具参数和场景用途。
- 不出现未提供的业务事实、品牌承诺、额外 Logo 或水印。
- 出错时只改错误点相关 prompt，不重写整个需求。
- 工具未成功返回图片时，不要把内部分析当作生图结果。

## 素材库

构造 prompt 前，素材库工具可用时先查素材。是否使用素材库图，由 agent 根据用户输入和素材库返回内容判断；有可用参考图时，选最合适的一张作为素材库参考图。

素材库处理：

- 使用素材库时，从 agent 判断可用的素材中选最合适的一张素材图，追加到 `referenceImageUrls` 最后。
- 使用素材库时，素材 `coverUrl` 进入真实参考图字段；`coverUrl` 是本次可用的参考图本体，不需要还原素材历史 prompt 里的输入图。
- 素材 `backfillParams.prompt`、分类名、素材库名只用于选图；不要直接复制、摘要或改写进实际工具 prompt。
- 选图时不要把素材历史 prompt 当成本次生成的前置条件，也不要据此要求用户补信息；历史 prompt 中的"图1/图2/参考图/输入图"不能作为跳过素材的理由。
- 用户需求很泛、素材库图又被选中时，prompt 不再额外扩写主视觉，只写用户原始需求、参考图角色和必要硬约束，让模型从参考图吸收视觉方向。
- 素材库图中可能有历史内容，prompt 只需要求不要照搬与用户输入冲突的内容；不要在未读图时推断具体冲突项。
- 不使用素材库时，跳过素材库图，不强制解释选择过程。
- 用户明确不要参考素材库时，不使用素材库素材。
- 素材库工具不可用、返回异常或字段缺失时，跳过素材库，不阻断生图。

调用工具前必须自检：

1. 用户明确要求参与的图片是否已经按原顺序进入真实参考图字段；未被要求使用的上传图是否没有误传。
2. 如选择素材库参考图，是否追加到参考图字段最后。
3. 如选择素材库参考图，实际 prompt 正文是否写明"参考图列表最后一张为素材库参考图"，并保持图生图轻提示；不能只写在生成说明里。
4. 未选择素材库时，是否未传素材库图。
5. 是否传了 `skillName: "doneai"`。
6. 最终 MCP 工具参数是否只使用该工具支持的字段。

有素材库图时，以下说明必须进入实际工具 prompt：

```text
参考图列表最后一张为素材库参考图，请基于用户输入参考该图生成；
不要照搬参考图中的旧文案、旧主题、旧数据或与用户输入冲突的内容。
无水印，无多余文字。
```

禁止在已选择素材库图时做以下事情：

```text
把素材 backfillParams.prompt 改写进生成 prompt
在未读取图片时描述参考图画面细节
按纯文生图方式重新杜撰完整画面
套用场景 Prompt 模块补充画面主题、风格、构图、光影
```

保存素材库仅在用户明确要求时执行：

1. 用当前图片的 `generateUuid` 查询 `recordId`。
2. 用 `recordId` 保存到素材库。
3. 不传空 `libraryId`，省略即保存到"个人办公"。
